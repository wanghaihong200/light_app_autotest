# 定位器集中管理 + 候选链兜底（开发团队不打标）

开发团队明确不在控件上打标（无 accessibility id / data-testid / 组件 id 约定），定位子系统因此成为框架第一等公民而非锦上添花：定位器集中在 Page 层管理并强制候选链（resource-id → 文本 → 层级 xpath 逐级兜底），失败时输出完整尝试轨迹；"定位器散落在用例内"由框架 lint 规则禁止。

## Consequences

- 定位脆弱是既定约束下的固有风险，缓解手段是纪律（集中管理）与证据（尝试轨迹），不是等待开发配合。
- 若日后开发团队松动，WebView 页面加 `data-testid` 是成本最低、收益最大的第一优先打标点。
