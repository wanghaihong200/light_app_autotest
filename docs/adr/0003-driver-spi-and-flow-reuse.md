# Driver SPI + 业务流程复用、页面实现分端

用例模型分三层：业务流程层（端无关，全产品线一份）、页面实现层（按端各写一份，暴露统一接口）、驱动层（每端一个 Driver，接口为引擎无关的 SPI）。鸿蒙（预计一年后，现有混合 App 移植形态）届时作为第三个 Driver 插入，上层零改动，现阶段不写任何鸿蒙代码。

## Considered Options

- **完全统一的跨端元素模型**（一份用例自动适配所有端）：小程序 automator 的元素模型（WXML 节点、page.data）与 WebView/原生差异过大，强行统一会产出不可维护的抽象层。拒绝。
- **各端用例完全独立**：失去业务流程复用，同一业务逻辑多端重复维护。拒绝。

## Consequences

- Driver SPI 的接口签名从第一天起禁止泄漏 Appium/automator 类型，这是鸿蒙能否低成本插入的前提。
- 小程序 DevTools 渲染 ≠ 真机渲染，小程序侧质量结论一律按"工具渲染"口径解读并写入报告。
